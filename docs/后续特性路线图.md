# 后续特性路线图：设置、用户资料、异步基础设施、站内信与音乐

> 状态日期：2026-09-27
>
> 文档状态：已确认方向，尚未进入编码
>
> 适用范围：现有模块化单体、Vue Web、MySQL/Flyway、local-first 账本与后续 NAS 能力
>
> 目标：把新增需求拆成可独立交付、可验证、可回滚的增量，避免一次性引入 Redis、RabbitMQ、通知和媒体处理后形成新的耦合。

## 1. 需求范围

本路线图覆盖五组后续能力：

1. **公共设置与模块设置分离**：全局设置只保留用户级、跨模块配置；工时、账本、音乐等设置回到各自模块。
2. **用户信息管理**：支持姓名、性别、生日/年龄展示、头像等个人资料，并为社交账号绑定预留安全的数据模型。
3. **Redis + RabbitMQ 异步基础设施**：用于缓存、限流、任务分发、失败重试、削峰和异步事件投递，但不替代 MySQL 权威数据。
4. **站内信与协作通知**：覆盖账本邀请、审批待办、定时任务执行结果、成员操作动态及后续任务提醒。
5. **独立音乐模块**：扫描个人 NAS 音乐库，在登录鉴权下提供曲库、在线播放、播放列表和收藏。

本路线图不改变当前主线结论：保持 Java 17 + Spring Boot 模块化单体，不拆微服务；所有数据库变更使用新的 Flyway 迁移；新模块继续受 Spring Modulith 与 ArchUnit 边界测试约束。

## 2. 当前基线与缺口

| 领域 | 当前已有 | 主要缺口 |
|---|---|---|
| 设置 | 单一 `/settings` 页面；包含主题、工时标准时间/午休/排班、工时数据导入导出、模型连接、MCP Token | 公共与领域设置混杂；缺少设置导航、统一保存状态和模块归属规则 |
| 用户 | 注册、登录、用户名、邮箱、密码、JWT、角色权限 | 缺少独立资料页、姓名/性别/生日/头像；社交账号绑定未建模 |
| 定时任务 | 账本周期流水、Spring Scheduling、ShedLock、手动执行、Agent 工具 | 缺少统一运行记录、通用重试/DLQ、任务中心和失败通知 |
| 审批与成员 | Agent R4 审批中心；账本成员/角色管理 | 新增成员仍偏管理操作，缺少“邀请—接受/拒绝—入账本”的协作流程 |
| 通知 | 页面 Toast、审批中心、审计日志 | 缺少持久化站内信、未读数、偏好、深链、批量已读和成员动态摘要 |
| 基础设施 | MySQL、Nginx、Spring Boot；部分进程内异步与持久队列 | 尚未部署 Redis、RabbitMQ；没有 outbox/inbox、消费者幂等和死信治理 |
| 文件/NAS | 架构文档已有 MinIO/NAS 与 file 模块规划 | 尚无文件域、对象鉴权、媒体扫描、Range 播放和音乐元数据 |

## 3. 已确定的架构原则

### 3.1 数据与中间件边界

- **MySQL 是唯一权威数据源**：用户资料、邀请、站内信、任务运行记录、音乐元数据和业务状态必须落 MySQL。
- **Redis 数据允许重建**：仅保存缓存、限流计数、短期幂等标记、在线状态、未读数加速和分布式协调信息；Redis 丢失不能造成业务数据丢失。
- **RabbitMQ 负责异步传递，不负责业务事实存储**：生产者在业务事务内写 `event_outbox`，提交后由发布器投递 RabbitMQ；消费者使用 `event_inbox` 或业务唯一键去重。
- **至少一次投递 + 幂等消费**：不追求虚假的“恰好一次”；重复消息必须安全，失败达到阈值后进入 DLQ，并支持人工重放。
- **同步主链优先**：账本记账、邀请接受、审批执行等用户必须立即知道结果的操作仍同步提交；队列只处理通知、索引、缓存失效、扫描、转码等后置工作。

### 3.2 模块边界

- 顶层“设置”是前端信息架构，不新建一个可以读写所有表的万能 `settings` 后端模块。
- 用户资料和社交身份归 `identity`；主题和界面偏好归用户偏好能力；模型连接/MCP 仍归 `ai`；工时设置归 `worktime`；账本设置归 `ledger`；音乐设置归 `music`。
- `notification` 只消费公开领域事件并生成通知，不直接修改账本、工时、任务或音乐表。
- `schedule` 只负责触发、运行记录和重试协调，具体业务执行器仍归所属领域模块。
- `music` 是独立核心域，只通过 `file`/存储适配器访问 NAS，不允许把本机绝对路径暴露给浏览器。

### 3.3 隐私与安全

- 性别为可选枚举，生日为可选日期；**不直接存储年龄**，年龄按生日和用户时区实时计算，避免每年批量更新。
- 头像只保存受控 `file_object_id` 或对象键，不接受任意外链作为长期方案。
- 社交账号使用 `provider + provider_subject` 唯一识别；访问令牌加密保存、最小化 scope，并提供重新认证、解绑和异常登录审计。
- 站内信中的敏感业务信息最小化展示；通知深链打开后仍由目标模块再次进行权限校验。
- 音频访问必须鉴权、限制为当前用户可访问的音乐源，并防止目录穿越、符号链接逃逸和猜测对象键。

## 4. 设置中心重构

### 4.1 目标信息架构

公共设置入口 `/settings` 只展示跨模块、用户级配置：

| 分组 | 路由建议 | 内容 |
|---|---|---|
| 个人资料 | `/settings/profile` | 显示名称、姓名、性别、生日、头像、时区、语言 |
| 账号与安全 | `/settings/security` | 邮箱、密码、登录会话、二次验证预留、账号注销 |
| 社交账号 | `/settings/connections` | OAuth/社交账号绑定、解绑、最近授权时间 |
| 外观 | `/settings/appearance` | 主题、强调色、深浅模式、减少动态效果 |
| AI 与模型 | `/settings/ai` | 模型接口、API Key、价格、默认模型、连接测试 |
| 外部集成 | `/settings/integrations` | MCP Token、后续 Webhook/第三方服务 |
| 通知偏好 | `/settings/notifications` | 类别开关、即时/摘要、免打扰、Web Push/邮件预留 |

模块设置保留在模块内部：

| 模块 | 路由建议 | 从现有设置迁入/新增 |
|---|---|---|
| 工时 | `/worktime/settings` | 标准上下班、午休、排班、工资口径、历史重算、工时数据导入导出/清理 |
| 账本 | `/ledger/settings` 或现有管理页的“设置”标签 | 账本资料、默认账户、分类与导入导出策略、周期任务默认值、成员通知偏好 |
| 任务 | `/tasks/settings` | 默认清单、提醒、番茄钟、日历显示策略 |
| 音乐 | `/music/settings` | NAS 音乐源、扫描规则、忽略目录、转码策略、音质和缓存 |

### 4.2 实施拆分

1. **先迁路由和页面，不改 API 语义**：把现有工时卡片移入 `WorktimeSettingsView.vue`，复用现有 store 和接口，保证行为不变。
2. **再拆组件和状态**：模型连接、MCP、外观、工时、数据导入导出分别形成可测试组件，禁止一个页面同时持有所有领域状态。
3. **补公共设置壳**：桌面侧栏 + 移动端分组列表；保存、错误、未保存离开提示使用统一交互。
4. **最后清理旧入口**：`/settings` 兼容跳转到 `/settings/profile`；旧锚点或书签保留一个发布周期。

### 4.3 验收标准

- 公共设置页面不再出现工资、上下班、午休、排班或工时数据操作。
- 工时设置迁移前后请求体、历史重算、revision 和错误语义一致。
- 每个模块设置可以独立加载失败，不阻断其他设置分组。
- 桌面、375px 移动端、键盘导航和深浅主题通过 E2E；旧 `/settings` 地址可达。

## 5. 用户资料与账号绑定

### 5.1 建议数据模型

```text
user_profile
  user_id              PK/FK
  display_name         展示名称
  legal_name           真实姓名，可选
  gender               UNSPECIFIED/MALE/FEMALE/NON_BINARY/OTHER/PREFER_NOT_TO_SAY
  birth_date           DATE，可选；年龄由此计算
  avatar_file_id       可选，关联 file_object
  timezone             默认 Asia/Shanghai
  locale               默认 zh-CN
  bio                   可选短文本
  revision/created_at/updated_at

user_external_identity
  id/user_id/provider/provider_subject
  display_name/avatar_url
  encrypted_access_token/encrypted_refresh_token/token_expires_at
  scopes/linked_at/last_used_at/revision
  UNIQUE(provider, provider_subject)
```

`app_user` 继续承载登录主身份、状态和唯一用户名/邮箱；展示资料不要继续堆入认证主表。头像落地时先实现 `file` 模块的最小对象存储切片，只支持头像上传、裁剪后版本和删除，不必等待完整 RAG。

### 5.2 API 与交互

- `GET/PUT /api/v1/profile`：读取和 revision 更新个人资料。
- `POST /api/v1/profile/avatar`、`DELETE /api/v1/profile/avatar`：限制图片类型、像素、文件大小，服务端生成标准尺寸。
- `GET /api/v1/profile/connections`：列出已绑定账号，不返回令牌。
- `POST /api/v1/profile/connections/{provider}/start`：生成带 state/PKCE 的授权流程。
- `DELETE /api/v1/profile/connections/{provider}`：重新验证当前账号后解绑；不得解绑最后一个可登录身份。

### 5.3 验收标准

- 资料读取与修改严格按当前用户隔离，revision 冲突返回 409。
- 生日跨时区计算年龄正确；生日、性别均允许留空。
- 头像上传拒绝伪造 MIME、超限图片和恶意文件；删除后回退默认头像。
- 同一外部账号不能绑定到两个用户；OAuth state、PKCE、回调地址和令牌加密通过安全测试。

## 6. Redis、RabbitMQ 与通用任务运行平台

### 6.1 Redis 首批用途

| 用途 | Key 示例 | 失效/一致性策略 |
|---|---|---|
| 用户资料/权限摘要缓存 | `user:{id}:profile:v{revision}` | 修改后删缓存；短 TTL；数据库回源 |
| 账本总览/报表缓存 | `ledger:{bookId}:overview:{queryHash}` | 流水/预算事件精确失效；短 TTL |
| 接口与 MCP 限流 | `rate:{dimension}:{window}` | Lua/令牌桶；Redis 不可用时采用保守本地限流或拒绝高风险请求 |
| 未读数加速 | `notification:{userId}:unread` | MySQL 为准；事件更新，定期对账 |
| OAuth state/验证码/短期幂等 | 带随机高熵 key | 严格 TTL，一次性消费 |

第一阶段不要缓存高频变化且难以正确失效的流水明细、审批状态和任务最终状态。所有缓存必须有命中率、回源数、失效数和数据版本指标。

### 6.2 RabbitMQ 拓扑

```text
event_outbox(MySQL)
    │ 发布器确认
    ▼
salary.domain.events (topic exchange)
    ├── notification.events
    ├── cache.invalidation
    ├── insight.events
    └── music.index.events

salary.jobs (direct exchange)
    ├── jobs.scheduled
    ├── jobs.file-scan
    ├── jobs.music-scan
    └── jobs.media-transcode

每个队列：主队列 → 延迟/重试队列 → DLQ
```

要求：

- publisher confirm、持久化消息、显式 consumer ack、合理 prefetch。
- 消息只放事件 ID、资源公共 ID、用户 ID 和必要摘要，不放完整文件、Token、密码或大段业务快照。
- 重试采用指数退避并带抖动；可重试错误与永久错误分类；达到上限进入 DLQ。
- 消费者先登记 inbox/幂等键，再执行副作用；重复消息返回成功但不重复通知、扫描或写数据。
- RabbitMQ 不可用时，业务事务仍可完成并保留 outbox；恢复后补投。积压超过阈值必须告警。

### 6.3 定时任务与失败重试

现有 ShedLock 保留为“到期扫描/触发器”，执行过程演进为：

```text
ShedLock 定时扫描
  → 创建 job_run（唯一业务键）
  → 写 outbox
  → RabbitMQ 分发
  → 领域执行器处理
  → job_attempt 记录结果
  → 成功/失败事件
  → 站内信与运维告警
```

建议表：

- `scheduled_job_definition`：任务类型、cron/规则、启停、所属模块、并发策略。
- `job_run`：计划时间、开始/结束、状态、业务唯一键、触发来源、当前尝试次数。
- `job_attempt`：每次执行节点、错误分类、脱敏错误摘要、耗时、下次重试时间。
- `event_outbox` / `event_inbox`：可靠发布与消费去重。

现有 `ledger_scheduled_task` 继续保存账本业务规则，不迁成通用表；通用任务平台只引用其公共 ID 并调用 ledger 公共执行器。

### 6.4 运维与验收

- Compose 新增 Redis、RabbitMQ 健康检查、持久卷、资源上限和备份/恢复说明；默认不暴露公网管理端口。
- 指标至少包括队列深度、最老消息年龄、发布失败、消费失败、重试数、DLQ 数、缓存命中率和 Redis 内存。
- Chaos 验证：Redis 重启、RabbitMQ 停机 10 分钟、消费者重复投递、应用处理后确认前崩溃、DLQ 人工重放。
- 退出门禁：核心同步业务在 Redis/RabbitMQ 短时不可用时不丢数据；同一任务/事件重复投递不重复产生业务副作用。

## 7. 站内信、审批与协作邀请

### 7.1 通知类型

| 类别 | 示例 | 默认策略 |
|---|---|---|
| `COLLABORATION` | 账本邀请、邀请接受/拒绝、成员移除 | 即时站内信 |
| `APPROVAL` | 有新的 R4 审批、审批通过/拒绝/过期 | 即时站内信 + 待办入口 |
| `JOB` | 周期流水执行成功、失败、重试耗尽、音乐扫描完成 | 失败即时；成功可按日摘要 |
| `ACTIVITY` | 其他成员新增/修改/删除流水、预算、分类 | 默认摘要，可按账本关闭或改即时 |
| `SYSTEM` | 安全提醒、服务升级、Token 即将过期 | 按风险即时 |
| `REMINDER` | 后续任务到期、日报生成 | 按用户偏好 |

### 7.2 数据模型与 API

```text
notification
  id/user_id/category/type/title/body/level
  actor_user_id/aggregate_type/aggregate_id/deep_link
  dedupe_key/read_at/archived_at/created_at/expires_at

notification_preference
  user_id/category/channel/frequency/enabled/quiet_hours/timezone/revision

ledger_invitation
  id/book_id/inviter_user_id/invitee_user_id
  target_username_or_email/role_id/status
  message/expires_at/responded_at/revision
```

首版 API：列表分页、未读数、单条/批量已读、归档、通知偏好、邀请创建/接受/拒绝/撤回。通知正文使用服务端模板和结构化变量生成，不允许生产者直接提交任意 HTML。

### 7.3 账本邀请状态机

```text
PENDING → ACCEPTED
        → REJECTED
        → REVOKED
        → EXPIRED
```

- 首版只邀请已注册用户；通过全局唯一用户名定位，后续再增加邮件邀请。
- 创建邀请只产生 `PENDING` 记录和站内信，**不立即创建有效成员**。
- 被邀请人接受时在同一事务中校验邀请、账本、角色、现有成员和权限，然后创建成员并将邀请置为 `ACCEPTED`。
- OWNER 转移、系统角色变更等高风险操作继续走审批中心；邀请和 R4 审批是两种不同状态机，只通过站内信与深链关联，不合并数据表。
- 重复接受返回已有结果，不产生重复成员；过期、撤回、失权邀请不可恢复执行。

### 7.4 成员操作动态

- 从现有审计/领域事件生成“谁在何时对哪个资源做了什么”的通知摘要。
- 默认只推送影响协作的数据：新增/删除流水、预算变更、成员/角色变化、账本设置变化；普通浏览和个人界面操作不通知。
- 高频事件按 `book_id + type + time_bucket` 合并，例如“张三等 2 名成员今天新增 12 笔流水”，避免通知风暴。
- 每个账本支持“即时 / 每日摘要 / 仅重要 / 关闭”，但安全、成员移除和权限变化不可完全关闭。

### 7.5 前端体验与验收

- 全局顶栏增加通知入口和未读角标；通知中心支持分类、未读筛选、批量已读、归档和深链。
- 移动端使用独立页面或 Drawer，不依赖 hover；通知到达可先使用 SSE，后续再增加 Web Push。
- 深链目标不存在或已失权时显示明确终态，不泄露资源标题或内容。
- 验收覆盖邀请并发接受、邀请过期/撤回、重复消息、未读数对账、通知偏好、摘要合并和跨用户隔离。

## 8. 音乐模块与个人 NAS 在线播放

### 8.1 定位和边界

`music` 作为独立模块提供个人音乐库，不与附件知识库或 RAG 混在一起。它可以复用 `file` 的存储适配器、签名 URL 和扫描任务，但拥有独立的元数据、索引、播放列表和权限。

首版目标：

- 配置一个或多个当前用户有权访问的 NAS 音乐源。
- 扫描目录并提取歌曲、艺术家、专辑、封面、时长、格式、码率等元数据。
- 支持曲库浏览、搜索、在线播放、播放/暂停、进度、音量、上一首/下一首。
- 支持收藏、播放列表、最近播放和跨设备播放进度。
- 支持 HTTP Range，拖动进度条不需要从头下载。

首版不做：公开分享、版权内容抓取、跨用户公共曲库、歌词网络聚合、复杂推荐算法和无损音频实时转码集群。

### 8.2 存储与播放链路

```text
NAS 音乐目录
  → MinIO/S3 适配器或受限只读挂载
  → music scan job
  → 元数据写 MySQL，封面写 file_object
  → 浏览器请求播放票据
  → 后端鉴权
  → Nginx X-Accel-Redirect / 短期签名 URL
  → Range 流式读取音频
```

音频字节不应长期经 Spring Boot JVM 转发；后端只负责鉴权和签发短期访问。若现有 NAS 无法通过 MinIO 暴露，可增加受限本地文件适配器，但必须限定根目录、规范化路径并拒绝符号链接逃逸。

### 8.3 建议数据模型

```text
music_source       NAS/S3 来源、根目录、扫描规则、状态、最近扫描
music_track        对象键、内容指纹、标题、时长、格式、码率、标签、状态
music_artist       艺术家
music_album        专辑、年份、封面 file_id
music_track_artist 多艺术家关系
music_playlist     用户播放列表
music_playlist_item 顺序、track_id
music_favorite     用户收藏
music_play_history 最近播放、位置、设备、播放时间
music_scan_run     扫描进度、增删改统计、失败摘要
```

文件身份优先使用相对路径 + 大小 + 修改时间的快速指纹，必要时后台补内容 hash；重命名时尽量识别为同一曲目，删除文件先标记 `MISSING`，保留播放列表引用一段时间后再清理。

### 8.4 扫描、转码与缓存

- 扫描任务由 RabbitMQ 分片执行，目录遍历、标签提取和封面处理分别幂等。
- 支持 MP3、AAC/M4A、FLAC、OGG 等浏览器兼容或可直放格式；浏览器不支持的格式再按需排队转码。
- 转码使用独立 worker/FFmpeg，输出缓存到 NAS 的派生目录；原文件永不覆盖。
- Redis 只缓存热门曲目元数据、搜索建议和短期播放票据；音频文件不放 Redis。
- 扫描/转码进度、成功、部分失败和重试耗尽发送站内信；详情进入任务运行中心。

### 8.5 UI 与验收

- 路由建议：`/music`、`/music/albums`、`/music/artists`、`/music/playlists`、`/music/settings`。
- 全局迷你播放器在模块切换时保持播放；移动端提供底部播放器 Sheet，避免与模块底栏重叠。
- 验收至少包含 1 万首曲目的分页/搜索、重复扫描幂等、目录重命名、文件缺失、Range 请求、并发播放票据、移动浏览器后台行为和 NAS 短时离线恢复。
- 安全门禁：用户 A 无法枚举或播放用户 B 的曲目；访问票据短时有效且不可扩大路径范围；日志不记录 NAS 凭据和完整本地路径。

## 9. 分阶段实施顺序

阶段编号使用 `F`（Future）前缀，避免与现有 Phase 0-6、Agent Phase 3A-D 混淆。

### F0：契约与页面归属冻结

- 盘点现有 `/settings` 每个字段、接口、store 和测试归属。
- 冻结通知类别、邀请状态机、通用任务状态机和事件信封。
- 确认 Redis/RabbitMQ 生产资源、NAS 接入方式和容量边界。
- 只改文档、契约测试和迁移设计，不改变生产行为。

**退出门禁**：字段迁移清单无遗漏；事件名、幂等键、重试分类和回滚策略可审查。

### F1：公共设置拆分与用户资料

- 新增设置壳和 `/worktime/settings`，迁出现有工时与工时数据卡片。
- 新增 `user_profile`、资料 API 和页面。
- 落地最小头像文件能力；社交账号先建表与接口契约，可按供应商逐个启用。

**退出门禁**：旧设置行为零回归；资料隔离/revision/头像安全测试通过；旧路由兼容。

### F2：Redis、RabbitMQ、Outbox 与任务中心

- Compose 和配置增加 Redis/RabbitMQ；建立健康检查、指标和本地开发脚本。
- 实现 outbox 发布器、inbox 幂等、重试/DLQ 和任务运行表。
- 先迁一个低风险用例（例如缓存失效或通知测试事件），再迁周期任务后置通知；不直接改造所有业务。

**退出门禁**：中间件停机不丢业务提交；重复投递无重复副作用；DLQ 可查询和受控重放。

### F3：站内信与账本邀请

- 上线通知中心、未读数、偏好、SSE 和任务结果通知。
- 把账本新增成员改造成邀请接受流程；现有成员管理能力保留给已加入成员的角色调整和移除。
- 接入 Agent 审批、定时任务失败和成员操作摘要。

**退出门禁**：邀请、审批、任务、动态四类主流程 E2E 通过；跨用户泄露为零；通知风暴有合并和限速。

### F4：NAS 文件基础与音乐 MVP

- 建立 file 存储适配器、NAS/MinIO 访问、播放票据和 Range 支持。
- 新增 music 模块、来源配置、全量/增量扫描、曲库/专辑/艺术家页面和播放器。
- 先支持浏览器可直接播放格式，转码功能使用开关关闭。

**退出门禁**：大曲库分页与重复扫描稳定；NAS 原始路径不外泄；桌面和移动端可连续播放并拖动进度。

### F5：音乐增强与异步运营

- 播放列表、收藏、最近播放、跨设备进度、增量扫描。
- FFmpeg 异步转码、失败重试、缓存清理和空间配额。
- 音乐扫描/转码站内信、运行中心、指标和告警。

**退出门禁**：扫描/转码可观察、可重试、可清理；原文件不被修改；配额和异常积压有告警。

## 10. 依赖关系与可并行项

```text
F0 契约冻结
 ├──→ F1 设置/资料 ───────────────┐
 └──→ F2 Redis/RabbitMQ/任务平台 ─┼──→ F3 站内信/邀请
                                  │
                    最小 file 能力┘
                           └──→ F4 音乐 MVP → F5 音乐增强
```

- F1 的路由拆分可与 F2 基础设施并行，但头像上传要等最小 file 能力。
- F3 依赖 F2 的可靠事件和任务运行记录；通知页面可以提前使用测试数据开发。
- F4 依赖 file/NAS 和 F2 的扫描任务能力，不依赖完整 RAG/Qdrant。
- 音乐 MVP 不阻塞任务域、Agent/MCP 和洞察域；它们只共享基础设施与通知公共能力。

## 11. 共同测试、发布与回滚门禁

每个增量必须完成：实现、Flyway、OpenAPI/生成客户端、模块边界测试、后端单测/真实 MySQL 集成、前端测试、必要 E2E、文档、服务刷新和独立本地提交。

共同检查：

- `cd backend && mvn test`
- `cd frontend && npm run api:check && npm test && npm run build`
- 涉及消息队列时运行 Redis/RabbitMQ 故障与重复投递专项测试。
- 涉及 NAS/音乐时运行路径安全、Range、断线恢复和大曲库性能测试。
- `git diff --check`

发布原则：

- 使用独立功能开关：`profile.enabled`、`notification.enabled`、`ledger.invitation-enabled`、`async.rabbit-enabled`、`music.enabled`、`music.transcode-enabled`。
- 先上线表结构和暗态消费者，再开启生产者，最后开放 UI。
- Redis/RabbitMQ 配置可回退到禁用状态；已写 outbox 和通知数据保留，不执行破坏性 down migration。
- 音乐模块关闭后不得影响工时、账本、Agent/MCP 或登录；NAS 离线只影响媒体访问和扫描。

## 12. 完成定义

这些后续能力只有在以下条件全部满足时才视为完成：

- 公共设置与各模块设置边界清晰，现有工时设置已完全迁出公共入口。
- 用户可以安全维护资料、头像和已启用的社交绑定，隐私字段均可选且可审计。
- Redis/RabbitMQ 故障不会导致权威业务数据丢失；任务失败可观察、可重试、可进入 DLQ。
- 账本邀请必须由受邀成员明确接受，审批、任务结果和成员动态均可在站内信查询。
- 通知支持未读、已读、归档、偏好、摘要、深链和跨用户隔离。
- 音乐文件继续保存在个人 NAS，应用可安全扫描和在线 Range 播放，不暴露原始路径或凭据。
- 所有新模块具备契约测试、权限测试、指标、告警、运行手册、功能开关和可操作回滚方案。
