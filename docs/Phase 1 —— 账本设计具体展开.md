## 已实现产品约定

当前导入采用“上传并解析预览 → 确认写入 → 刷新账本”的阶段式进度展示。随手记多 Sheet 文件按 Sheet 名识别转账、支出、收入、借入、借出、收债和还债；仅支出、收入要求二级分类，其他类型允许无分类。源文件成员列不参与成员创建或匹配，所有导入流水统一归属当前登录用户在当前账本中的成员记录。
首页、账户管理和报表的总资产按资产账户余额加未收回借出本金展示；借入资金仍计入资产，其对应负债在净资产中扣除。实际账户余额记录借贷及转账两端的资金进出，新增/修改/删除流水后刷新账户余额。记一笔优先排列近期常用账户和两级分类，成员默认当前登录用户；收入与支出必须选二级分类，转账和债权债务流水不显示分类。月度日历的日期可跳转到该日流水。
自然语言记账先匹配当前账本已有的账户、一二级分类、商家、成员和项目；模型识别但未匹配的名称必须保留在草稿中提示用户选择或清除，不能静默丢弃。每笔草稿均可审核流水类型、金额、日期、账户、转入账户、一级/二级分类、商家、成员、项目和备注，未指定成员时默认当前登录用户。模型只返回一级分类时提示补充二级分类，分类不存在或名称有歧义时提示用户选择。首页记一笔、流水新增/编辑、AI 草稿、周期流水和流水筛选统一使用可输入的两级分类匹配器：一级、二级名称输入后实时过滤，二级支持输入“一级 / 二级”完整路径，选中二级后自动回填一级。收入/支出草稿没有匹配到有效二级分类时禁止确认写入，转账和债权债务流水不要求分类但转账必须选择转入账户。确认接口会再次校验账户、转入账户、成员和二级分类，不能通过绕过前端提交无效流水。报表当前 Tab 可导出 PNG 图片或通过浏览器打印保存 PDF。
随手记重复导入按“完整流水指纹在源文件中的出现序号”与账本已有数量比较：既避免同一文件重复写入，也保留同日、同金额且其他字段相同的真实多笔流水；收入/支出未填写一级分类时，指纹和落库统一按“其他”处理。导入完成后立即刷新账户派生余额和账本有效流水数量，流水增量同步转入后台并按分页批量写入 IndexedDB，不再逐条开启本地事务或为刷新页面重新拉取全部历史。
前端按登录用户 ID 隔离账本 IndexedDB、当前账本选择和工时本地缓存；退出或直接登录另一账号时必须无条件清理 access token、取消旧同步并清空 Pinia 内存状态，不能删除各用户自己的离线库，也不得将旧用户缓存上传到新用户服务端。普通 HTTP 环境不保证 `crypto.randomUUID` 可用，成员新增及本地 oplog 幂等键统一使用带 UUID v4 回退的客户端 ID 工具。
离线同步引擎 v1 位于 `frontend/packages/sync-engine`，流水、账户、分类、商家、项目和预算均通过 command facade 先写本地投影与 oplog；成员/角色、账本管理、导入、AI 确认、定时任务与回收站命令明确要求联网。周期流水执行规则采用二选一模式：固定日期可选择每周星期几、每月几号、每月第几周星期几、每年几月几号；间隔执行可选择仅一次或每 N 天/周/月/年。短月的 29—31 日按月末执行，第 5 周星期几不存在时跳过当月。

搜索仍属于后续阶段；当前已实现新建账本、跨账本复制、账本内报表和回收站。AI 已覆盖文字和图片识别，尚不包含 RAG、知识库或跨域 Agent。

当前实现约定：账本侧边栏在“账户”后、“管理”前提供独立“报表”入口，路由为 `/ledger/reports`。main 顶部使用横向 Tab 切换基础统计、分类、账户、商家、月报、支出分类、收入分类、账户详情、成员、项目分类和项目；右上角“报表库”支持将报表添加到 Tab 或从 Tab 移除，Tab 可拖动排序，配置和顺序保存在本机。统计范围使用上期/当前/下期按钮与按年、按月弹层选择器，当前报表和日期写入 URL，刷新后保持不变。基础统计按双列卡片布局，收支、结余和记账里程碑合并展示，收入、支出分类层级分别在各自统计卡片内切换。报表数据以当前账本 IndexedDB/Pinia 数据为主，断网仍可查看；图表统一使用 ECharts，并适配窄屏和深色主题。当前报表支持 PNG 图片导出和浏览器打印保存 PDF。

首页和报表的时间选择器同时支持按月、按年及自由起止日期；长于 93 天的自由范围趋势按月聚合，较短范围按日展示。所有分布类图表统一使用“图表扇区/柱条—排行图标—细进度线”一致配色：排行行左侧名次与图标留明显间隔，右侧名称与占比、金额排在条形进度图上方，细进度线从名称下方向右占满剩余宽度；一级分类按账本内顺序使用黄金角步进分配不同色系，二级分类在所属一级分类色相内使用不同明度和饱和度；导入自动创建分类时由后端写入同样的父子色系。账户、商家、成员和项目按实体稳定分配颜色，避免刷新后颜色跳变。页面路由切换、报表 Tab 切换、弹层及排行展开均使用短过渡动画，并遵循 `prefers-reduced-motion`；路由、数据刷新、保存、删除和导出等异步等待场景显示统一 loading 遮罩。
首页首次进入同样优先使用 IndexedDB/Pinia 投影，禁止为账户、分类、流水、月度统计和年度统计重复发起阻塞式全量请求；年度趋势由本地流水投影计算，月份切换只轻量刷新预算。图表实例应持续复用，卡片设置、时间范围和主题变化只更新图表配置。
报表首屏先使用 IndexedDB 中的当前账本投影渲染，服务端流水与预算刷新改为后台更新；账本切换完成后由 Pinia 响应式数据直接刷新报表，不重复打开遮罩读取同一份数据。路由和报表遮罩必须在成功、异常、组件卸载及安全超时时清理，禁止内容已可操作但遮罩仍阻塞页面。

## 成员管理
成员只能按已注册用户名添加；用户名在系统内唯一，邮箱另有唯一约束，暂不使用手机号识别。新增时必须联网由服务端检查用户存在、账号可用且尚未加入当前账本，失败时在弹窗中提示原因并保留输入；重新添加已移除成员可恢复原成员记录。
添加成功后，被添加者登录自己的账号可在“管理 → 账本管理”看到共享账本（标明自身角色）并切换；不在侧边栏或各页面单独放置切换器。当前选择按登录用户分别保留。重新联网或返回前台刷新成员可见列表，失去访问权时切回自己有权访问的账本。成员可查看共享数据并操作自己的流水，账户等资源管理和其他成员流水的写入须由对应角色授权，后端按成员关系逐请求校验。自己的默认账本不因加入共享账本而改变归属。
