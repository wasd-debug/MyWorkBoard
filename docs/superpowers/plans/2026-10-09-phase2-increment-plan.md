# Phase 2 任务域增量执行计划

> 状态：P2-0 决议已确认，待从 P2-I1 开始实施
> 规格：`docs/Phase 2 —— 任务域需求文档.md`
> 原则：Phase 2 最终仍交付完整个人版能力；P0 跨多个可运行增量完成，不组织为一次性大版本。

## 已冻结决策

- 首个增量直接交付“收件箱中新建、查看、编辑、完成、重新打开和删除任务”的纵向闭环。
- I2 先让任务核心写入与清单进入 local-first；后续资源随各自增量接入相同同步契约。
- 重复任务保留当前历史实例并生成下一实例，使用 `series_id + planned_due_at` 幂等。
- 提醒首版由 task 模块自建站内信、ShedLock 扫描、SSE 和轮询，不引入 MQ 或 Web Push。
- 协作列、协作表和附件表不提前创建；设置字段按实际功能通过新 Flyway 迁移递增。
- 跨域日历由 app 组装层调用各模块公开只读接口，task 不读取工时或账本表。
- 前端只运行 Node、类型、OpenAPI 和生产构建等非浏览器门禁；页面行为写入手工检查清单，由用户验收。

## 增量顺序

| 增量 | 交付结果 | 主要退出门禁 |
|---|---|---|
| P2-I1 | task 模块、V30、收件箱和在线任务闭环 | 用户隔离、幂等、revision、模块边界、构建通过 |
| P2-I2 | 任务核心写入与清单 local-first | 离线重放、op 幂等、冲突/拒绝、账号隔离 |
| P2-I3 | 清单/标签/子任务/检查项、五视图、垃圾桶 | 树恢复、分页筛选、同步完整性 |
| P2-I4 | 重复实例、提醒、任务站内信 | 实例零重复、提醒误差不超过 1 分钟、重启/并发安全 |
| P2-I5 | 日/周/月日历、农历、跨域只读叠加 | 分层降级、改期 revision、关闭农历零退化 |
| P2-I6 | 番茄钟、习惯、倒数日 | 计时恢复、连续重算、与工时口径隔离 |
| P2-I7 | 看板/四象限/智能清单、搜索、统计、导入导出 | 解析零写入、真实 Excel 验收、公式注入防护 |
| P2-I8 | task Agent/MCP、ICS、设置与最终收口 | prepare 零写入、commit 幂等、订阅安全、完整退出门禁 |

I6 可在 I4 稳定后与 I5 并行；数据库迁移、同步协议和 Agent 写工具保持串行。E1 多人协作与 Phase 4 附件能力不属于本计划。

## 每个增量的完成动作

1. 只提交该增量所需代码、迁移和文档，不混入无关文件。
2. 更新 `ARCHITECTURE.md`、`overview.md`、Phase 2 需求文档及受影响的部署说明。
3. 用户可见流程必须更新 `docs/前端手工检查清单.md`，自动化结果与待人工项目分开记录。
4. 运行比例合适的 Maven、真实 MySQL、Node、类型、OpenAPI、生产构建和 `git diff --check`。
5. 刷新受影响的本地服务；若被环境阻塞，先在文档和交付说明中记录。
6. 创建一个仅包含该增量的中文 conventional commit；不自动推送或部署。

## P2-I1 开工边界

P2-I1 只建立当前闭环必需的数据：默认收件箱、任务核心字段、最小任务设置和必要审计/索引。暂不建立标签、检查项、提醒、重复实例、协作、附件、番茄、习惯、倒数日、全文索引或 ICS 表。V30 与首批 OpenAPI 契约评审通过后，才开始页面和服务实现。
