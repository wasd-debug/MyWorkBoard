## 1. 文档目的与范围

### 1.1 目的

本文档定义"任务域"这一独立业务模块的完整需求，使其能够：

1. 覆盖滴答清单的核心与进阶能力：清单、任务、子任务、重复、提醒、标签、优先级、多视图、番茄钟、习惯、倒数日、统计、导入导出。
2. 作为第四个一级模块嵌入现有工作台导航，与工时、账本、AI 工作台并列。
3. 满足仓库既有工程门禁：Spring Modulith 模块边界、Flyway 版本化迁移、`/api/v1/tasks/**` 唯一契约、OpenAPI 生成客户端、IndexedDB + oplog local-first、ArchUnit 依赖方向校验。
4. 为后续 `task.*` Domain Tool 注册（Phase 3A-D）与 Phase 5 跨域洞察提供数据与事件基础。

### 1.2 范围内

- 任务域的数据模型、API、前端页面、离线同步、通知与设置。
- 与工时打卡、账本流水在**日历视图**中的叠加展示（只读聚合，不建立强事务耦合）。
- 任务域 Agent 只读查询与受控写入工具的设计目标（实现排在 Phase 3D 之后）。

### 1.3 范围外（本阶段不做）

- **任务协作（多人分配、评论 @、团队清单、共享清单）**：本期不实现，但数据模型、权限模型、状态机与 API 轮廓已在**附录 B** 完整设计，作为 Phase 2 之后的扩展项排入，避免后期推倒重来。
- 附件与文件：延后到 Phase 4 `file` 模块落地后接入；本期只保留接口设计，不提前建表或建立悬空外键。
- 完整 RAG、向量检索、跨域 AI 报告（Phase 4 / Phase 5）。
- 移动端原生 App、桌面客户端。仅保证 Web 响应式（桌面 / 平板 / 手机）。
- 滴答清单官方 API 双向实时同步（官方 API 为会员付费能力且不稳定，本阶段只做 **Excel / CSV / ICS 离线导入**）。
- Web Push 与邮件提醒：本期不做，走站内信最小实现；设计见 T-206 与 T-703。

### 1.4 术语表

| 术语                  | 含义                                        |
| ------------------- | ----------------------------------------- |
| 清单（List）            | 任务的容器，等价于滴答清单的"清单"。有名称、颜色、图标、视图模式、排序。     |
| 清单分组（Folder）        | 清单的上一级容器，可嵌套一级，用于收纳多个清单。                  |
| 收件箱（Inbox）          | 系统默认清单，每个用户唯一且不可删除；未指定清单的任务默认落入收件箱。       |
| 智能清单（Smart List）    | 由用户自定义筛选条件动态生成的虚拟清单，不落业务数据，只读聚合。          |
| 任务（Task）            | 最小执行单元，可含子任务、检查项、标签、提醒、重复规则。              |
| 子任务（Subtask）        | 挂在父任务下的独立任务，拥有自己的到期日和完成状态；父任务不因未完成子任务被阻塞。 |
| 检查项（Checklist Item） | 任务内的轻量勾选清单，无独立到期日和提醒，不参与筛选统计。             |
| 番茄（Focus Session）   | 一次专注计时记录，可关联任务。                           |
| 习惯（Habit）           | 周期性重复的行为打卡，独立于普通任务，有连续天数与完成率。             |
| 倒数日（Countdown）      | 以目标日期为核心的纪念日/倒计时卡片，不是任务。                  |
| 视图（View）            | 同一批任务的不同呈现方式：列表、日历、看板、时间线（甘特）、四象限。        |
| 修订号（revision）       | 乐观锁版本号，与账本域一致，冲突返回 409。                   |
| 公共 ID（public_id）    | 对外暴露的 UUID，数据库自增主键不出现在 API 中。             |

## 3. 产品目标与非目标

### 3.1 目标

1. **个人任务闭环**：从"想到一件事"到"完成并回顾"全流程在本站完成，不再依赖外部 App。
2. **与既有模块共生**：日历视图同时看到打卡、记账与任务；番茄钟与工时互相印证专注投入。
3. **离线优先**：断网可新建、完成、修改任务，联网后无丢失、无重复。
4. **可被 Agent 驱动**：任务能力完成后注册为 `task.*` 工具，让 AI 工作台能查、能建、能改（受控）。

### 3.2 非目标

- 不追求与滴答清单 UI 像素级一致，只要求能力对等。
- 不做多租户团队协作与组织权限。
- 不引入超过单机部署复杂度的中间件（F2 之前任务域不依赖 Redis/RabbitMQ）。

### 3.3 优先级定义

| 级别     | 含义                                 |
| ------ | ---------------------------------- |
| **P0** | Phase 2 核心范围，允许拆成多个独立增量交付；全部 P0 完成后才通过核心门禁 |
| **P1** | 滴答清单高频能力，第二批交付                     |
| **P2** | 滴答清单进阶/会员等价能力，第三批交付，可延后            |

P0 不再等同于“一次性大版本”。每个增量必须形成可运行、可验证、可回滚的纵向切片；Phase 2 最终完成标准仍保持第 12 章定义的完整个人版能力范围。

## 5. 详细功能需求

每条需求编号 `T-xxx`，标注优先级与验收要点。

### 5.1 清单与清单分组

#### T-101 清单（P0）

描述：任务的顶层容器。

规则：

- 字段：公共 ID、名称（1-100 字符，trim 后非空）、颜色（取自主题色板枚举）、图标（Lucide 图标名枚举）、排序序号、是否收藏、视图模式（LIST / BOARD / CALENDAR / TIMELINE）、归档标记。
- 每个用户默认存在唯一 `收件箱` 清单：`is_default=true`，不可重命名、不可删除、不可归档。
- **清单数量不设上限**（已确认）：不引入"免费用户清单数限制"。性能上按用户分页加载清单树，单个用户清单超过 200 个时侧栏改为搜索式折叠，避免长列表卡顿。
- 清单支持排序：手动拖拽排序（持久化 `sort_order`）。
- 清单支持归档：归档后从清单导航隐藏，其任务默认不在"今天/最近7天"等视图中展示（可通过"显示归档清单任务"开关临时打开）。
- 清单删除：软删除进垃圾桶，其下任务一并软删除并可在回收站整体恢复；删除前展示影响预览（任务数、其中未完成任务数、子任务数）。

验收：

- 收件箱不可删除接口返回 409 且前端入口置灰。
- 删除清单后其任务进入回收站，恢复后清单与任务关系完整还原。
- 归档清单任务不出现在"今天"视图。

#### T-102 清单分组 Folder（P1）

规则：

- 分组只支持一级，不支持分组嵌套分组。
- 清单可归入 0 或 1 个分组；未分组清单平铺在导航顶部。
- 删除分组时其下清单变为未分组，不删除清单。
- 分组支持折叠/展开（状态本地持久化）。

#### T-103 清单模板（P2）

规则：预置"旅行准备""周复盘""搬家"等模板，一键创建清单及其任务骨架；支持把现有清单另存为模板。

#### T-104 智能清单 Smart List（P1）

规则：

- 由用户定义的筛选条件集合动态生成，不落业务数据。
- 可配置维度：清单集合、标签集合（任一/全部）、优先级集合、状态（未完成/已完成/全部）、到期时间范围（相对：今天/明天/最近7天/逾期/无日期；绝对：起止日期）、关键词、是否含子任务。
- 条件之间为 AND，集合内部可切换 ANY / ALL。
- 智能清单支持排序、置顶、重命名、改条件、删除；删除不影响任务。
- 智能清单内可完成任务、改期，等同于列表视图操作；不支持"移动到本清单"（虚拟容器）。

验收：条件变更后列表实时重算；任务满足条件即刻出现、不满足即刻消失；跨用户不可见。

### 5.2 任务核心模型

#### T-201 任务字段（P0）

| 字段   | 类型                                           | 说明                                                 |
| ---- | -------------------------------------------- | -------------------------------------------------- |
| 标题   | 文本 1-500                                     | 必填，trim 后非空                                        |
| 描述   | 长文本                                          | 支持轻量 Markdown（粗体、斜体、列表、链接、代码）；渲染时做 HTML 转义与链接协议白名单 |
| 所属清单 | 引用                                           | 必填，默认收件箱                                           |
| 到期时间 | datetime + 全天标记 + 时区                         | 可只给日期（全天）；可给开始+结束时间段                               |
| 开始时间 | datetime                                     | 可选，与结束时间组成时间段；日历视图按时间段渲染                           |
| 持续时间 | 分钟                                           | 时间段展示的等价表达，与开始/结束互推                                |
| 优先级  | 枚举 NONE/LOW/MEDIUM/HIGH                      | 对应滴答清单 0/1/2/3，UI 用旗标颜色区分                          |
| 标签   | 多值引用                                         | 见 T-204                                            |
| 重复规则 | RRULE 字符串                                    | 见 T-202                                            |
| 状态   | 枚举 OPEN/DONE                                 | 完成写入 `completed_at`                                |
| 排序序号 | 数值                                           | 清单内手动排序                                            |
| 来源   | 枚举 WEB/QUICK_ADD/RECURRENCE/IMPORT/AGENT/API | 审计用                                                |

规则：

- 用户时区默认 `Asia/Shanghai`，跟随用户设置。
- 全天任务的到期时间为该日 00:00（本地时区），且不参与"逾期分钟"计算，只在跨日后显示为逾期。
- 标题支持 emoji，禁止控制字符。
- 描述长度上限 20,000 字符；标题 500；单任务标签数上限 20。

验收：缺少标题返回 400 且带字段级错误；超长返回 400；XSS 载荷在渲染时为纯文本。

#### T-202 重复规则（P0）

规则：

- 使用 RFC 5545 RRULE 子集：`FREQ=DAILY|WEEKLY|MONTHLY|YEARLY`，支持 `INTERVAL`、`BYDAY`、`BYMONTHDAY`、`BYMONTH`、`COUNT`、`UNTIL`。
- 提供快捷预设：每天、每个工作日、每周（可多选星期）、每 N 天、每月（按日/按第 N 个星期 X）、每 N 月、每年、自定义 RRULE。
- 循环基准二选一：**按到期日期**（固定周期，逾期也按原节奏生成）或 **按完成日期**（完成后才生成下一次）。默认按到期日期。
- 重复任务按“实例留存”建模：完成当前实例后，当前任务保持 `DONE` 和原完成时间，服务端生成下一条 `OPEN` 实例；已完成列表、统计和审计直接读取历史实例，不通过重置同一行模拟历史。
- 同一系列使用稳定的 `series_id` 关联，各实例使用递增 `series_sequence`；生成下一实例由服务端在完成动作或 ShedLock 到期扫描中完成，使用 `series_id + planned_due_at` 保证幂等。
- `COUNT` 耗尽或超过 `UNTIL` 时不再生成下一实例；按完成日期规则只有当前实例完成后才生成下一实例。
- 修改重复任务时区分"仅本次"和"整个系列"：仅本次生成例外实例并脱离系列；整个系列修改规则本身。
- 删除重复任务同样区分仅本次 / 整个系列。

验收：

- 每日规则连续完成 3 次只产生 3 条历史，不产生重复。
- 按完成日期规则在未完成时不推进。
- 到期扫描重复执行不生成重复实例。
- 例外实例修改不影响系列其他实例。

#### T-203 子任务（P0）

规则：

- 子任务挂在父任务下，支持最多 2 层嵌套（父 → 子 → 孙）。
- 子任务拥有完整任务字段（到期日、优先级、标签、提醒），但默认继承父任务清单，不单独出现在清单导航。
- 父任务不因子任务未完成而被阻塞；父子完成状态独立。
- 父任务列表项展示进度 `已完成子任务数 / 子任务总数`。
- 父任务完成时不自动完成子任务（弹出确认：仅完成父任务 / 连带完成全部子任务）。
- 父任务删除时级联软删除子孙任务，回收站按树恢复。
- 子任务可提升为独立任务（移动到指定清单）。

验收：级联软删与树形恢复完整；进度计数正确；层级超限返回 400。

#### T-204 标签（P0）

规则：

- 标签为**用户级**资源：名称 1-30 字符，trim 后去重（大小写不敏感），颜色可选。
- 任务与标签为多对多；删除标签时先解除所有关联（预览展示被引用任务数），不删除任务。
- 标签支持重命名（全局生效）、合并（把 A 合并入 B）。
- 标签树：滴答清单支持标签层级（`#工作/#工作/项目A`），用 `parent_id` 表达，路径以 `/` 连接展示；筛选父标签时包含子标签。

验收：同名创建返回 409；删除标签后任务标签引用清零且不产生孤儿记录；跨用户标签不可见。

#### T-205 检查项 Checklist（P1）

规则：

- 任务内嵌的轻量勾选列表，字段：内容（1-500）、是否完成、排序序号。
- 无独立到期日、提醒、标签，不参与筛选与统计。
- 支持拖拽排序、批量清空已完成项、把检查项转换为子任务。
- 任务卡片展示 `n/m` 进度。

#### T-206 提醒 Reminder（P0）

规则：

- 一个任务可有多个提醒。
- 提醒类型：
  - **相对提醒**：相对到期时间提前 N 分钟/小时/天（滴答清单常见：准时、提前 5/10/15/30 分钟、1 小时、1 天）。
  - **绝对提醒**：指定日期时间点（可早于或晚于到期日）。
- 全天任务的默认提醒时间为当日 09:00（用户可改）。
- **投递通道（已确认）**：本期只做**站内信最小实现**（见 T-703），即任务域自有的提醒收件箱 + 顶栏角标 + SSE 实时到达（SSE 建连失败降级 30 秒轮询）。字段层预留 `channel` 枚举（IN_APP / PUSH / EMAIL）与用户偏好，Web Push 与邮件**本期不实现**，留待 F3 通知中心与公网 HTTPS 稳定后接入，不改动 API 语义。
- 未完成任务的提醒在任务完成/删除/进入垃圾桶后取消；已投递的不再重投。
- 逾期任务提供"每日提醒直到完成"开关（默认关）。
- 提醒投递延迟目标 ≤ 1 分钟；ShedLock 扫描周期 30 秒，扫描窗口带重叠避免漏扫；同一提醒用唯一键（reminder_id + fire_date）保证只投一次。
- 提醒记录默认保留 90 天；已读/忽略状态可持久化，避免角标长期累积。

验收：

- 提醒准点误差 ≤1 分钟（验收时记录实际偏差）。
- 重复扫描、应用重启、并发实例下不重复投递。
- 完成任务后未投递提醒被取消。

#### T-207 任务活动日志 Task Activity（P1）

规则：

- 记录任务生命周期事件：创建、修改（字段级前后值）、完成、取消完成、删除、恢复、改期、移动清单、加/去标签、提醒触发、番茄关联。
- 在任务详情以时间线倒序展示，分页加载。
- 只保留最近 12 个月（与审计保留策略一致）。

### 5.3 视图

#### T-301 列表视图（P0）

内置视图：收件箱、今天、明天、最近 7 天、全部、已完成、垃圾桶。

规则：

- **今天** = 到期时间 ≤ 今日 23:59 且未完成（含逾期）。
- **明天** = 到期时间在明日全天。
- **最近 7 天** = 今日起 7 天内到期（含逾期分组）。
- **已完成** = 状态 DONE，按完成时间倒序，支持按日期分组。
- **垃圾桶** = 软删除任务，支持恢复与永久清除（永久清除按 R4 审批语义在任务域内做二次强确认）。
- 列表支持排序：手动（仅清单内）/ 到期时间 / 优先级 / 标题 / 创建时间。
- 列表支持分组：无 / 清单 / 优先级 / 到期日期 / 标签。
- 支持"显示已完成"开关（默认关）。
- 支持分页与游标加载，页大小默认 50。
- 过期任务在列表中置顶分组并标红展示逾期天数。


验收：五个内置视图口径与滴答清单一致；排序与分组切换不丢数据；跨用户零泄露。

#### T-302 日历视图（P0，年视图 P2）

规则：
- 使用 FullCalendar 提供日 / 周 / 月视图，自研年视图（12 个月缩略热力 + 任务密度）。
- 周视图支持"多日切换"（3 日 / 5 日 / 7 日），月视图支持"多周切换"（2 周 / 4 周 / 6 周）。
- 移动端（≤1024px）默认日/周视图；桌面端默认月视图；视图偏好按用户持久化。
- 支持在日历上拖拽任务改期、拖拽边缘改持续时间。
- 叠加显示（只读聚合，不建立事务耦合）：
  - 工时打卡记录（来自 worktime 域，展示上下班区间与加班时长）
  - 账本流水（来自 ledger 域，展示当日收支净额）
  - 法定节假日与调休（来自 holiday 表）
  - 习惯打卡状态
  各叠加层可独立开关，任一来源接口失败只降级该层并提示，不阻断日历渲染。
- **农历（已确认引入第三方农历库）**：
  - 选型建议：后端引入 `cn.6tail:lunar-java`（6tail/lunar-java，Apache-2.0，纯 Java 无网络依赖，覆盖 1900-2100 年农历、二十四节气、干支、生肖、传统节日与法定节假日推算）；前端不重复实现，统一由 `/api/v1/tasks/calendar` 下发 `lunarDate` 字段（如 `八月十五`）、节日名与节气名。
  - 展示位置：日历日视图与月视图的日期标签、倒数日卡片、任务详情的到期日括号补充。
  - 降级策略：`task.lunar-enabled` 开关关闭或数据超出库支持年份范围时，仅不显示农历文本，日历与任务主流程不受影响。
  - 约束：农历计算只在后端执行，前端不做二次推算；库版本与数据边界写入依赖清单，升级需回归 1900/2100 边界与闰月用例。

验收：
- 四视图切换流畅、无横向溢出。
- 拖拽改期生成正确的 revision 与活动日志，失败可回滚。
- 关闭工时或账本后日历仍完整可用（模块解耦门禁）。
- 移动端无 hover-only 操作。

#### T-303 看板视图（P1）

规则：
- 列维度可选：清单 / 状态 / 优先级 / 标签。
- 卡片展示标题、到期日、优先级旗标、子任务进度、标签。

### 5.4 交互能力

#### T-401 快速添加与自然语言解析（P1）

规则：
- 全局快捷入口（顶栏 + 快捷键）唤起输入框。
- 解析规则（服务端优先，失败时前端兜底）：
  - 日期时间词：`今天 / 明天 / 后天 / 下周一 / 3月5日 / 10月7日 15:00 / 每天 / 每周一 / 每月1号`
  - 优先级：`!` 数量（1=LOW，2=MEDIUM，3=HIGH）或 `p1/p2/p3`
  - 标签：`#标签名`
  - 清单：`@清单名`（不存在时提示是否新建）
  - 提醒：`提前30分钟`、`提醒我9点`
- 解析结果以结构化字段回填到可编辑的表单卡片，用户确认后才落库。解析不确定时保留原文并高亮未识别片段。
- 前端可复用现有 AI 模块做解析（可选开关 `task.nlp-parse-enabled`），但**必须**服务端二次校验日期与枚举合法性；AI 不可用时有纯规则兜底。

验收：常见 20 条中文表达解析正确率记录留档；解析失败不产生脏数据。

### 5.5 效率工具

#### T-501 番茄钟（P1）

规则：
- 设置：专注时长（默认 25 分钟）、短休息（5 分钟）、长休息（15 分钟）、长休息间隔（4 个番茄）、自动开始休息、自动开始下一番茄、白噪音（可选，需素材，P2）。
- 计时基于**服务端时间戳**而非前端累加：开始记录 `started_at` 与计划结束时间，刷新/锁屏/切后台后按时间差恢复，误差 ≤2 秒。
- 可关联任务；番茄结束时把实际专注分钟累加到任务（`task.focus_minutes`）与该番茄记录。
- 记录字段：用户、关联任务、计划时长、实际时长、开始/结束时间、是否完成（中途放弃记为 `ABORTED` 并保留实际时长）、来源设备标签。
- 统计：今日/本周/本月/本年番茄数与专注时长；按任务、清单、标签分布；连续专注日历热力图。
- 提供全屏专注模式；页面切换时计时继续（全局迷你计时器常驻顶栏）。
- **与工时域的关系（已确认）**：番茄专注时长**不写入工时记录**，也不参与加班分钟、实际时薪与工资快照的任何计算。两个域只在统计页做只读对照展示（同一时间轴叠加"专注时长"与"在岗净工时"），并在 UI 上明确标注两者口径不同（番茄是主动专注，工时是打卡区间），避免用户把两者相加。
- 边界要求：`task` 模块不得调用 `worktime` 的写入接口或工时计算服务；对照数据通过只读查询契约获取，工时域不可用时对照视图降级隐藏。

验收：刷新页面计时不中断、不跳变；同用户并发开启番茄只允许一个进行中；放弃的番茄时长正确保留。

#### T-502 习惯打卡（P1）

规则：
- 习惯字段：名称、图标、颜色、目标频率（每天 / 每周 N 次 / 每月 N 次 / 自定义星期）、每日目标次数、提醒时间、开始日期、归档标记。
- 打卡：次数 +1，支持补卡（指定历史日期，限制不早于习惯开始日期）、跳过（记为 SKIP，不计入连续也不中断连续）。
- 指标：当前连续天数、最长连续天数、30 天完成率、本月完成/目标。
- 展示：周视图网格 + 年度热力图 + 趋势折线。
- 连续计算规则：目标周期内达标才算连续；SKIP 不中断；连续按用户时区自然日判定。
- 归档习惯保留历史，不再出现在打卡列表。

验收：跨时区连续天数正确（以用户时区为准）；补卡后连续重算准确；重复打卡同一日期幂等。

#### T-503 倒数日 / 纪念日（P2）

规则：标题、目标日期、类型（倒数日/纪念日）、是否每年重复、置顶、备注、配色。展示"还剩 N 天 / 已过 N 天 / 今天是第 N 周年"。排序按最近目标日期。与日历视图叠加显示。

### 5.6 数据能力

#### T-601 导入（P1）

- **支持格式（已确认含 Excel）**：
  - **Excel**：`.xlsx` / `.xls`，复用后端已有 **EasyExcel** 依赖（账本导入已使用），支持多 Sheet 选择、首行表头识别、合并单元格按首格取值。这是用户手上现有数据的主通道。
  - **CSV**：`.csv`，UTF-8 / GBK 自动探测（中文 Excel 另存常见编码），逗号与分号分隔符兼容。
  - **ICS**：标准 `.ics`（滴答清单导出、其他日历工具导出）。
  - 滴答清单官方导出为 CSV，Excel 一般为自建台账，两者共用同一套字段映射配置。
- 字段映射（Excel/CSV 通用，支持用户在预览页调整列映射）：标题、描述、清单、到期日期、到期时间、开始日期、优先级（0-3 或 低/中/高）、标签（多值分隔符 `,`/`;`/`|`）、重复规则文本、提醒（分钟或绝对时间）、子任务（通过"父任务标题"或缩进层级识别）、完成状态与完成时间。
- 与账本导入保持一致的三阶段：文件预览 → 结构化摘要（有效行 / 重复行 / 错误行，逐行给出原因） → 确认导入。**导入前零写入**。
- 无法识别的清单自动创建；重复规则尽力映射（中文"每天/每周一/每月1号"→ RRULE），无法映射的降级为普通任务并在摘要中提示。
- 重复判定：同一用户下按 `清单 + 标题 + 到期时间` 生成指纹，命中已存在任务则标记为重复行，默认跳过、可勾选覆盖。
- 限制：单文件 10 MB，10,000 行，Sheet 数上限 20（与账本导入一致）。
- 导入不进入 LLM 上下文；服务端不持久化上传文件，确认后即弃。
- **验收素材**：用户已有的 Excel 台账作为 I7 的真实用例，需覆盖表头别名、中文日期格式、空行、合并单元格与重复行五类情况。

#### T-602 导出（P1）

- 导出 CSV、Excel（EasyExcel）与 ICS；CSV/Excel 增加公式注入防护（`=`/`+`/`-`/`@` 开头单元格前缀转义）。
- 导出走受认证接口下载，服务端不持久化临时文件。

#### T-603 ICS 订阅 Feed（P2）

- **已确认可公网暴露**：站点已有公网服务器与域名，订阅地址走与站点相同的 HTTPS 域名，路径 `/api/v1/tasks/feed/{token}.ics`。
- 每个用户生成带随机高熵 token（≥128 bit）的只读订阅地址，可轮换、可撤销；服务端只存 token 哈希。
- 只输出未完成任务（含 VALARM），不输出描述全文（可开关，默认只输出标题与到期时间，降低信息泄露面）。
- 访问无需登录，但必须：token 不可枚举、按 IP + token 限流（建议 60 次/小时）、响应头禁止缓存或设置短 `max-age`、Nginx 不记录完整 URL（日志脱敏 token）。
- 轮换后旧地址立即失效；用户可在设置页一键轮换与撤销全部订阅。

#### T-604 任务统计与回顾（P1）

- 指标：新建数、完成数、完成率、逾期完成数、平均完成时延、按清单/标签/优先级分布、番茄专注时长、习惯完成率。
- 时间粒度：日 / 周 / 月 / 年，使用 ECharts。
- 首版实时聚合（数据量小），Phase 5 上线后切换 `report_fact` 快照。

#### T-702 离线同步（task 域）（P0）

规则（照搬 ledger 同步契约）：
- 复用 `sync-engine`，新增 `task` 域：`task`、`task_list`、`task_tag`、`checklist_item`、`focus_session`、`habit_checkin` 走 command facade + oplog。
- 写入顺序：先更新 IndexedDB 投影与 oplog（离线可用），再由 sync-engine 推送；在线命令由 store 统一拒绝离线伪成功。
- 按用户隔离本地缓存，切换账号清空重投。
- 分页拉取 + 游标；冲突（revision 不匹配）与校验拒绝进入独立队列并在 UI 明示。
- 幂等键：客户端生成 `op_id`，服务端按 `user_id + op_id` 去重。
- 跨资源命令（导入、永久清除、恢复、批量）明确要求联网。

验收：断网新建/完成/修改/删除 → 刷新保留 → 重连同步 → 无丢失无重复；服务端真实 MySQL 集成测试与 sync-engine Node 测试覆盖幂等、冲突、拒绝和账号隔离；页面离线流程记录到 `docs/前端手工检查清单.md`，由用户手工验收。

#### T-703 提醒投递与通知角标（P0）

**已确认：本期采用站内信最小实现，不引入 RabbitMQ，也不等 F3 通知中心。**

最小实现范围：
- 任务域自建两张表：`task_inbox_message`（站内信，含类型/标题/正文/关联任务/深链/已读时间/创建时间）与 `task_reminder_fire`（投递去重记录）。
- 投递由 ShedLock 扫描直接写入 `task_inbox_message`，不经过消息队列。
- 到达方式：SSE 推送（`GET /api/v1/tasks/inbox/stream`），建连失败或被代理缓冲时降级为 30 秒轮询 `GET /api/v1/tasks/inbox/unread`。
- 顶栏提醒入口显示未读数与逾期数角标；提醒中心页面支持未读筛选、单条/批量已读、清空、点击跳任务详情。
- 用户偏好：免打扰时段、每日摘要时间、按提醒类型开关——落在任务设置表，后续通过 `task_setting` 的独立迁移扩展，不依赖全局通知偏好表。

迁移路径（F3 之后的既定动作，不在本期）：
- 保留 `/api/v1/tasks/inbox/**` 语义不变，把写入端切到 `notification` 模块、投递切到 RabbitMQ，历史消息迁移进统一通知表。
- 前端入口从"任务提醒"升级为全局通知中心的一个分类筛选，组件复用。
- **本期的硬约束**：不得在 `task` 模块内引入 MQ 客户端依赖；不得让 `task_inbox_message` 被其他模块直接读写。

#### T-704 Agent / MCP 工具注册（P1，依赖 Phase 3A-D）

设计目标（实现排在 3D 之后，本阶段只预留契约）：
- R1 只读：`task.list.query`（按清单/日期/标签/优先级筛选）、`task.today`、`task.overdue`、`task.stats.summary`、`habit.checkin.query`、`focus.stats.query`。
- R2 prepare/commit：创建任务、完成任务、改期（低风险，单条）。
- R3 prepare/commit：修改任务字段、删除任务。
- R4 审批：批量删除、永久清除、导入确认。
- 遵循既有规则：`*.commit` 不直接暴露给 MCP，外部写入统一走 `agent.action.commit`；prepare 零业务写入；commit 幂等。
- 工具命名落在 `task.*` 命名空间，随 Domain Tool Registry 自动接入 MCP 可见性推导。

#### T-705 附件（P2，Phase 4 后接入）

- 本阶段不建立 `task_attachment` 表，也不建立指向尚不存在 `file_object` 的外键。
- Phase 4 `file` 模块具备对象存储、鉴权和稳定公共 ID 后，再通过独立 Flyway 迁移增加 `task_attachment`；未启用时 UI 不展示入口。

| GET/POST/PUT/DELETE | `/api/v1/tasks/{publicId}/reminders/**` | 提醒 |
| GET | `/api/v1/tasks/{publicId}/activity` | 活动日志（分页） |
| GET | `/api/v1/tasks/calendar` | 日历聚合：`from`、`to`、`layers=worktime,ledger,holiday,habit`；`lunar=1` 时下发农历日期、节气与节日名（后端 6tail lunar 计算） |
| GET | `/api/v1/tasks/board` | 看板聚合：`dimension=list\|status\|priority\|tag` |
| GET | `/api/v1/tasks/quadrant` | 四象限聚合 |

| POST | `/api/v1/tasks/import/commit` | 导入确认 |
| POST | `/api/v1/tasks/export` | 导出（受认证下载） |
| GET | `/api/v1/tasks/feed/{token}.ics` | ICS 订阅（token 鉴权，无需登录，公网 HTTPS，限流 + 日志脱敏） |
| POST/PUT/DELETE | `/api/v1/tasks/feed/token` | 生成/轮换/撤销订阅 token |
| GET | `/api/v1/tasks/inbox` | 站内信列表（分页、未读筛选） |
| GET | `/api/v1/tasks/inbox/unread` | 未读数与逾期数（角标，SSE 降级时的轮询入口） |
| GET | `/api/v1/tasks/inbox/stream` | SSE 实时到达（30 秒心跳，断连自动重连） |
| POST | `/api/v1/tasks/inbox/read` | 单条/批量已读（幂等） |
| DELETE | `/api/v1/tasks/inbox` | 清空已读（保留未读） |
| GET/POST/PUT/DELETE | `/api/v1/tasks/habits/**` | 习惯 CRUD |
| POST | `/api/v1/tasks/habits/{publicId}/checkin` | 打卡 / 补卡 / 跳过（幂等） |
| GET | `/api/v1/tasks/habits/{publicId}/stats` | 连续、完成率、热力图 |
| GET/POST/DELETE | `/api/v1/tasks/focus/sessions` | 番茄记录（开始用幂等键，结束用 revision） |
| GET | `/api/v1/tasks/focus/stats` | 专注统计 |
| GET/POST/PUT/DELETE | `/api/v1/tasks/countdowns/**` | 倒数日 |
| GET/PUT | `/api/v1/tasks/settings` | 任务设置（revision） |
| GET/POST | `/api/v1/tasks/sync/push` `/pull` | 离线同步（复用 sync-engine 契约） |

约定：
- 分页统一 `page`（从 0）/ `size` / `sort`，返回 `content` + `total` + `page` 元信息，与账本一致。
- 写操作：新增用幂等键请求头，修改/删除用 `revision`；冲突返回 409 + `ApiProblem`。
- 所有 ID 使用 `public_id`，自增主键不出现在响应体。
- 时间字段统一 ISO-8601 带时区偏移；全天任务返回日期 + `isAllDay=true`。
- 新增接口同步进入运行时 OpenAPI，并刷新 `frontend/packages/api-client/src/generated`。

| 详情 Drawer | 560px（<768px 全屏 Sheet） | 覆盖在内容区右侧，不挤压列表；列表保持滚动位置 |
| 顶部工具条 | 与内容区同宽 | 滚动时 sticky 吸顶（`position: sticky; top: 0`） |

**侧栏分区顺序**：内置视图 → 智能清单（可折叠）→ 清单树（可折叠，含分组）→ 标签（可折叠）→ 习惯 / 专注 / 倒数日。

| `habitStore` | 习惯与打卡 | `habits`、`checkins`、`stats` |

| `countdownStore` | 倒数日 | `items` |

| `taskSettingsStore` | 任务设置与视图偏好 | `settings`、`viewPrefs` |
| `taskSyncStore` | task 域离线同步（推送/拉取/冲突队列） | `online`、`pending`、`conflicts`、`rejected` |

数据流约定（照搬账本）：
- 写操作一律经 `taskCommands` facade：先更新 IndexedDB 投影 + oplog → UI 立即反映 → sync-engine 推送 → 服务端 revision 回写。
- 在线专属命令（导入、永久清除、批量 >200）由 store 直接拒绝离线伪成功，不进 oplog。
- 页面只从 store 读，不在组件内直接调 transport；组件禁止持有跨页面的领域状态。


### 8.7 多端弹性布局体系

#### 8.7.1 现状问题与收敛原则

`theme.css` 现存 13 个临时断点值（340 / 400 / 420 / 430 / 560 / 640 / 720 / 767 / 820 / 900 / 1024 / 1100 / 1400），是各页面按需硬编码累积的结果。任务域**不得再新增任何临时断点值**，统一收敛到 4 个语义前缀。

收敛原则：
1. **媒体查询只管「页面骨架」**（侧栏常驻还是抽屉、详情走 Drawer 还是 Sheet）；**组件内部布局一律用容器查询**。原因：任务内容区的真实宽度会被「侧栏折叠」和「详情 Drawer 挤压」改变，视口宽度测不出来。
2. 断点值只定义一次，放在 `theme.css` 的 `@theme` 块，任务域 CSS 只引用前缀。
3. 能靠 `auto-fit` / `clamp()` 自适应解决的，不写断点。

#### 8.7.2 断点阶梯（唯一来源）

项目用 Tailwind CSS v4（`@tailwindcss/vite`，无独立 config，token 写在 CSS 的 `@theme` 块）。为避免与 Tailwind 默认的 `sm/md/lg/xl/2xl` 数值语义混淆，任务域使用**语义前缀**：

```css
/* src/styles/theme.css —— @theme 块内新增，仅此一处定义 */
@theme {
  --breakpoint-phone:   640px;   /* 大屏手机及以上 */
  --breakpoint-tablet:  768px;   /* 平板竖屏及以上 */
  --breakpoint-desktop: 1024px;  /* 桌面骨架启用：侧栏常驻、底栏收起 */
  --breakpoint-wide:    1440px;  /* 宽屏：内容区可并排容纳列表 + 详情 */
}
```

| 前缀 | 生效条件 | 任务域语义 |
|---|---|---|
| `phone:` | ≥640px | 任务行显示清单·标签列；四象限由单列转 2×2 |
| `tablet:` | ≥768px | 看板列宽由 78vw 转 280px；详情 Dialog 可用（非全屏） |
| `desktop:` | ≥1024px | 侧栏常驻、浮动底栏收起、详情走 Drawer |
| `wide:` | ≥1440px | 内容区最大 1180px 居中；详情可常驻并排 |

反向变体用 Tailwind 的 `max-*`：`max-desktop:` 表示 <1024px。任务域 CSS 中**禁止出现** 340/400/420/430/560/720/820/900/1100/1400 这类字面量。

#### 8.7.3 弹性布局原语（按优先级）

| 优先级 | 手段 | 用途 | 示例 |
|---|---|---|---|
| 1 | **容器查询** | 组件随父容器宽度自适应 | `@container taskContent (max-width: 520px)` |
| 2 | **内在式栅格** | 卡片/列数不写死 | `repeat(auto-fit, minmax(min(280px, 100%), 1fr))` |
| 3 | **流式排版** | 字号/间距随视口平滑变化 | `font-size: clamp(18px, 1rem + 0.6vw, 26px)` |
| 4 | **断点媒体查询** | 仅用于页面骨架切换 | `@media (min-width: 1024px)` → `desktop:` |
| 5 | 固定值 | 仅 Drawer/Sheet 宽度、触控热区下限 | `560px` / `44px` |

容器查询承接点（现有先例，直接推广）：`LedgerView.vue` 已用 `.ledger-summary-grid :deep(.card){container-type:inline-size}`。任务域对应写法：

```css
.task-content  { container-type: inline-size; container-name: taskContent; }
.task-row      { display: grid; grid-template-columns: auto minmax(0,1fr) auto; gap: 10px; }

/* 内容区被详情 Drawer 挤窄时，隐藏次要列而不是溢出 */
@container taskContent (max-width: 520px) {
  .task-row-meta   { display: none; }
  .task-row-desc   { -webkit-line-clamp: 1; }
}
```

硬约束：所有 grid 轨道写 `minmax(0, 1fr)` 而非 `1fr`（防止内容撑破，现有代码已普遍遵守）；图片与嵌入媒体统一 `max-width: 100%; height: auto`。

- **高度一律 `dvh`**：首屏稳定布局用 `svh`；**任务域禁止新增 `100vh`**（`theme.css` 现存的 6 处 100vh 为遗留，不在任务域范围内改，但新代码不得模仿）。
- 底部预留：移动端页面 `padding-bottom: calc(92px + env(safe-area-inset-bottom))`，沿用 `theme.css:1138` 现有规则；批量操作条 `bottom: calc(84px + env(safe-area-inset-bottom))` 避让浮动底栏。
- 左右安全区：所有 `position: fixed` 元素（底栏、批量条、悬浮 AI）加 `env(safe-area-inset-left/right)`，横屏刘海机必须内缩。
- 软键盘：Sheet 内输入聚焦时，用 `visualViewport` 监听把 Sheet 底部抬到键盘之上；**不要用 `position: fixed` 直接顶**（iOS Safari 会抖动）。输入区加 `scroll-margin-bottom` 保证光标可见。
- 顶栏高度沿用现有变量：桌面 88px、移动端 64px；`min-height: calc(100dvh - 88px / 64px)` 对应计算。

#### 8.7.7 折叠屏、横竖屏与多窗口

- **紧凑高度模式**：`@media (max-height: 600px) and (orientation: landscape)` 触发——顶栏降到 56px、页面头部副标题隐藏、日历日视图刻度压缩到 40px/小时、番茄全屏改为左右分栏（数字左、统计右）。主要针对手机横屏与折叠屏展开横屏。
- **折叠屏展开（717–840px）**：按 `tablet:` 处理；同时满足 `max-height: 540px` 时叠加紧凑高度模式。
- **双屏设备（Surface Duo 类）**：不特殊适配，按两个 ~540px 视口处理；任务域只需保证 540px 下无横向溢出。
- **分屏 / 自由缩放**：禁止任何依赖固定窗口宽度的 JS 计算；窗口 resize 不重新挂载组件——用 `ResizeObserver` 只切布局类，保证番茄计时不重置、列表滚动位置不丢失。
- **横竖屏切换**：监听 `orientationchange` + `ResizeObserver`，不触发路由重建；番茄计时始终以服务端时间戳恢复（见 8.4.7），切屏不丢进度。

#### 8.7.8 输入方式适配

- 用 `@media (hover: hover) and (pointer: fine)` 区分精确指针；触屏设备不依赖 hover（架构既有门禁：禁止 hover-only 核心操作）。
- 触控热区最小 44×44px，相邻热区间距 ≥8px；任务行复选框热区扩展到整行左侧 48px 宽。
- 手势：左滑 = 完成 / 删除（可在设置切换），长按 = 多选；**每个手势必须有等效可见按钮**（无障碍要求，不能只有手势）。
- 拖拽：桌面用原生拖拽，触屏一律提供菜单替代路径（8.8 已列）。拖拽期间用 `transform` 位移，放下后才提交 revision。

#### 8.7.9 字号与缩放弹性

- 任务域新增样式**字体一律 `rem`/`em`，禁止 `px`**（热区尺寸等几何量除外）。
- 满足 WCAG 1.4.10 Reflow：320px 宽等效视口下无双向滚动；支持浏览器 200% 缩放与系统大字号。
- 长文本 `overflow-wrap: anywhere` + `hyphens: auto`，任务标题不因单个长 URL 撑破布局。
- 列表密度偏好（设置项「紧凑 / 舒适」）只改 CSS 变量 `--task-row-h: 44px | 56px`，不改 DOM 结构。

#### 8.7.10 JS 侧断点的统一入口

禁止在各组件里散落 `window.matchMedia`。统一为一个 composable，仅在「组件结构必须替换」时使用（Drawer ↔ Sheet、列表 ↔ 卡片）；纯样式差异一律交给 CSS。

```js
// src/composables/useViewport.js
export function useViewport() {
  const width  = ref(window.innerWidth)
  const height = ref(window.innerHeight)
  const isDesktop      = computed(() => width.value  >= 1024)  // 与 --breakpoint-desktop 对齐
  const isCompactHeight = computed(() => height.value <= 600)
  // ResizeObserver + visualViewport 监听，节流 100ms；首屏同步计算一次避免闪烁
  return { width, height, isDesktop, isCompactHeight }
}
```

断点数值在 CSS `@theme` 与 JS 各存一份，**必须保持一致**（在 `useViewport.js` 顶部注释标注对应关系，避免两处漂移）。

### 8.10 主题与无障碍

- 颜色只走语义 token（`--card`、`--ink`、`--ink2`、`--muted`、`--line`、`--accent`、`--accent-soft` 等），**禁止硬编码颜色**。

## 9. 后端模块设计

新增 Maven 物理模块 `backend/modules/task`，包名 `com.salarytracker.task`。

分层（与 ledger 对齐）：
```text
com.salarytracker.task

├── domain/       领域模型、重复规则求值、连续天数计算、四象限判定
├── infra/        JDBC/MyBatis-Plus repository、Flyway 资源、ShedLock 扫描器
```

第三方依赖（新增）：
- `cn.6tail:lunar-java`：农历与节气计算。封装在 `infra/lunar/LunarCalendarAdapter`，领域层只依赖自研接口 `LunarCalendar`，禁止领域类直接引用第三方类型（保证可替换与可测试）。

- `task` 不得直接访问 `worktime` / `ledger` 表，也不承担跨域日历编排。由 `app` 组装层建立只读日历聚合服务，分别调用 task、worktime、ledger 的公开查询接口；对外路径仍可保持 `/api/v1/tasks/calendar`，任一叠加层失败只降级该层。

- 新增模块必须纳入 `ArchitectureBoundaryTest` 的依赖方向与源码目录归属校验，违规即构建失败。
- 提醒扫描使用既有 ShedLock 模式，F2/F3 之后迁移到通用任务运行平台。

## 11. 分期实施计划

编号调整为 `P2-I1` … `P2-I8`。P0 是跨多个增量完成的核心范围，不再等同于首个大版本。每个增量必须完成：实现 → 必要 Flyway → OpenAPI/生成客户端 → 模块边界测试 → 后端单测与真实 MySQL 集成 → 前端 Node/类型/OpenAPI/生产构建 → 手工检查清单更新 → 服务刷新 → 独立本地提交。不得使用浏览器自动化、截图或交互式浏览器代替用户手工验收。

### P2-I1：收件箱任务纵向切片
- 新建 `task` 模块并纳入 ArchUnit；V30 只建立收件箱清单、任务核心表、最小设置表及必要索引。
- 交付收件箱中的任务新增、查看、编辑、完成、重新打开和软删除；前端提供 `/tasks/inbox` 最小列表与详情编辑（已完成）。
- I1 为控制首批索引与页面输入规模，标题/描述先按 255/4,000 字符落库；在 I3 引入完整编辑能力时通过新迁移扩展至 T-201 的 500/20,000 字符，不改写已应用 V30。
- **门禁**：真实用户隔离、幂等创建、revision 冲突、收件箱初始化和生产构建通过；用户可在线完成完整任务闭环。

### P2-I2：核心 local-first
- 先覆盖任务新增、编辑、完成、重新打开和删除，再覆盖清单；接入 IndexedDB 投影、oplog、push/pull、冲突与拒绝队列。
- **门禁**：sync-engine Node 测试与真实 MySQL 集成覆盖离线重放、op 幂等、revision 冲突、校验拒绝和账号隔离；页面流程由用户手工验收。

### P2-I3：任务组织与基础视图
- 增加清单管理、标签、子任务、检查项、排序、移动、五种列表视图、垃圾桶恢复和分页筛选。

## 12. 总体验收标准（退出门禁）

Phase 2 任务域只有在以下条件全部满足时才视为完成：

1. **功能对等**：第 4 章列入 Phase 2 的 P0/P1/P2 个人版能力全部完成，包括清单、任务、重复、提醒、多视图、年视图、时间线、番茄钟、习惯、倒数日、导入导出和 ICS；仅明确依赖 Phase 4 的附件与 Phase 2 之后的 E1 协作除外。
2. **离线可靠**：断网可完成全部核心写入，重连后无丢失、无重复、冲突可见可处理。
3. **提醒准时**：准点误差 ≤1 分钟，重复投递为零，任务完成后未投递提醒被取消；站内信未读数与角标对账一致。
4. **模块解耦**：关闭工时或账本后任务域完整可用；任务域关闭后其他模块完整可用；关闭 `task.lunar-enabled` 后日历零退化。
5. **权限隔离**：跨用户读取、修改、删除、订阅、导入均为零泄露；ArchUnit 边界测试通过（含"task 模块不得依赖 worktime 写入接口与 MQ 客户端"两条新约束）。
6. **口径隔离**：番茄专注时长不进入工时、加班、时薪与工资的任何计算，对照页口径标注清晰。
7. **导入真实用例**：用现有 Excel 台账完成一次端到端导入，有效/重复/错误行判定准确，预览零写入。
8. **公网订阅安全**：订阅地址 HTTPS 可达、token 轮换后旧链接立即失效、越权枚举为零、访问日志不含明文 token。
9. **工程门禁**：`cd backend && mvn test` 全绿（按既有规则跳过的除外）；`cd frontend && npm run api:check && npm test && npm run build` 通过；OpenAPI 生成无差异；`git diff --check` 通过。
10. **多端布局门禁**：按 8.12 的 15 档视口矩阵逐档通过——含 320px 极小屏、折叠屏展开横屏（717×512）、手机横屏、1280×800 @ 200% 缩放、分屏半屏与横竖屏来回切换；8.7.11 的十条禁止清单零违反（无 `100vh`、无新临时断点、无横向溢出、无 hover-only、fixed 元素均有安全区避让）；深浅四套主题对比度达标、键盘可达、axe serious/critical 零违规。
11. **真机留档**：Android Chrome 与 iOS Safari 各执行一次真机验收，记录设备、系统与浏览器版本。
12. **协作扩展可迁移**：本期不建立未使用的协作列或表；单用户契约、公共 ID、创建者审计和模块边界清晰，E1 可通过独立迁移兼容扩展。

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| RRULE 求值复杂，跨时区/月末/闰年易出错 | 使用成熟 RRULE 库并在领域层单测覆盖月末（1/31 → 2/28）、闰年、DST、跨时区；禁止手写日期递推 |
| 提醒漏投或重投 | 扫描窗口重叠 + 唯一投递键 + 幂等；记录投递结果并对账 |
| 番茄计时在移动端后台被节流 | 基于服务端时间戳恢复，不依赖前端定时器累加 |
| 离线同步是最高复杂度资产，返工代价高 | 直接复用 ledger 已验证的 sync-engine 与 command facade 模式，先小域验证再全覆盖 |
| 日历叠加把模块耦合在一起 | 叠加只做只读聚合编排，失败降级单层，禁止跨模块事务 |
| 自然语言解析产生脏数据 | 服务端二次校验 + 结构化草稿确认后才落库，AI 不可用时规则兜底 |
| 表结构与索引设计不当导致后期返工 | I1 冻结核心主键、公共 ID 与索引语义，后续通过新迁移扩展，禁止改写已应用迁移 |
| 一次性引入过多能力导致不可回滚 | 功能开关 + 分 I1-I8 增量提交，每个增量独立可回滚 |
| 公网暴露 ICS 订阅被枚举或爬虫滥用 | token ≥128 bit 且只存哈希；按 IP+token 限流；日志脱敏；一键轮换/撤销；订阅默认不输出描述全文 |
| 第三方农历库版本漂移或数据边界不足 | 封装在 `LunarCalendarAdapter` 后，领域层只依赖自研接口；锁定版本并登记支持年份；单测覆盖 1900/2100 边界、闰月与节气；异常时降级不显示 |
| Excel 导入的编码、合并单元格与脏表头导致错列 | 多 Sheet 显式选择 + 首行表头识别 + 列映射可调整 + 编码探测；预览阶段逐行给出有效/重复/错误原因，零写入；以用户现有台账做真实用例 |
| 站内信最小实现后期与 F3 通知中心重复建设 | 本期固定 `/api/v1/tasks/inbox/**` 语义与 `dedupe_key` 约束，F3 只做写入/投递端迁移；禁止 task 模块引入 MQ 依赖（ArchUnit 校验） |
| 番茄时长被误当成工时参与薪酬计算 | 已确认不写入工时域；ArchUnit 约束 `task` 不得依赖 `worktime` 写入接口；统计页明确标注两者口径不同 |

## 附录 B：多人协作扩展设计（E1，Phase 2 之后实现）

> 本节为**后续设计**。本期不写实现代码、不建立协作列或协作表；E1 开工时以独立迁移实现，`task.collaboration-enabled` 默认关闭。

### B.1 定位

把"个人任务"升级为"可共享的清单"，能力对齐滴答清单的协作清单：清单共享给其他已注册用户、任务指派给成员、任务评论与 @、成员动态通知。不引入组织/团队概念，只做**清单级**协作。

### B.2 核心概念

| 概念 | 说明 |
|---|---|
| 清单所有者 OWNER | 创建者，唯一，拥有全部权限且不可被移除 |
| 成员 MEMBER | 通过邀请接受进入清单，按角色获得权限 |
| 角色 ROLE | OWNER / EDITOR / COMMENTER / VIEWER；系统角色不可删除 |
| 指派 ASSIGNEE | 任务的负责人，默认创建者；一个任务最多一个指派对象 |
| 评论 COMMENT | 任务下的讨论，支持纯文本与 @提及，不进入 MCP 工具 |

### B.3 状态机

邀请状态机（复用 F3 账本邀请的同一套语义，不合并数据表）：

```text
PENDING → ACCEPTED
        → REJECTED
        → REVOKED
        → EXPIRED
```

- 创建邀请只产生 `PENDING` 记录并发送站内信，**不立即创建有效成员**。
- 接受时在同一事务内校验邀请、清单、角色、现有成员与权限，然后创建成员并将邀请置为 `ACCEPTED`。
- 重复接受返回已有结果，不产生重复成员；过期、撤回、失权邀请不可恢复执行。
- OWNER 转移、删除清单等高风险操作继续走 Agent R4 审批中心；邀请与审批是两种状态机，只通过站内信与深链关联。

### B.7 通知与事件

- 协作类通知全部走 F3 的 `notification` 模块，类别 `COLLABORATION`：邀请发出/接受/拒绝/撤回、成员移除、任务指派、任务评论 @提及。
- 高频事件按 `list_id + type + 时间桶` 合并（如"张三等 2 名成员今天新增 12 条评论"），避免通知风暴。
- 深链目标不存在或已失权时显示明确终态，不泄露资源标题与内容。

### B.8 离线同步的影响

- 共享清单的数据**不进入本地 IndexedDB 投影**（只缓存个人私有清单），避免跨用户数据落本地。
- 共享清单页明确要求联网；断网时只读展示最近一次拉取的快照并标注"离线数据可能过期"，写入操作禁用。
- sync-engine 的 `task` 域过滤条件增加 `visibility = PRIVATE`。

### B.9 上线顺序与门禁

1. 前置：F3 站内信与账本邀请已上线、RabbitMQ/outbox 稳定。
2. 建表与暗态消费者 → 开启 `task.collaboration-enabled` → 灰度单人共享 → 开放 UI。
3. **退出门禁**：跨用户越权读写为零；邀请并发接受不产生重复成员；共享清单离线不落本地；关闭开关后退回纯个人模式且数据完整。
4. Agent 侧：`task.*` 工具在协作开启后必须叠加清单成员权限校验，R3/R4 写入继续走审批。
