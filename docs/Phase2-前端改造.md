## 1. 文档目标

本文档记录按逆向证据重做任务页的完整规格与增量进度，不以原有 TaskWorkspace 壳层或契约化的旧组件实现作为视觉基线。目标是复刻参考页的布局、交互与功能范围，保留个人工作台的视觉风格和本项目数据/API 边界。

本文档的产品参考来自对用户已登录的滴答清单 Web 任务页的界面观察。布局、功能范围和可见交互以已保存的逆向证据为准，个人工作台可保留自己的色彩、字体和品牌风格；不复制参考产品源码、私有接口或品牌资产。实现继续使用本项目现有 API、权限、同步和数据边界。

## 3. 参考页面已确认事实

### 3.1 整体布局

- 桌面端在全局模块栏内使用三栏任务工作区：左侧任务导航、中间任务列表、右侧任务详情。
- 观察视口中，全局模块栏约 `68px`，任务导航约 `222-240px`，中栏约 `658px`，右栏约 `505px`。
- 中栏最小宽度约 `370px`，右栏最小宽度约 `320px`。
- 右栏与中栏之间有约 `5px` 拖动分隔条，鼠标为 `ew-resize`，可改变详情栏宽度。
- 三栏占满可用高度，导航、列表和详情各自控制纵向滚动。
- 右栏是常驻详情编辑器，不是 Drawer；组织对象的轻量编辑可使用居中 Dialog。

### 3.2 任务导航

- 固定视图包含所有、今天、明天、最近 7 天、指派给我、收集箱和摘要。
- 清单、过滤器、标签是独立可折叠区域；标题左侧为折叠箭头，右侧为新增或更多操作。
- 过滤器标题菜单提供“显示”和“隐藏”；标签标题菜单提供“有内容时显示”“显示”和“隐藏”。这类可见性设置应落到本项目对应分区状态中。
- 清单项可展示图标、颜色、数量和归属分组；过滤器可表达本周、下周、无日期、无标签等条件。
- 底部还有已完成、已放弃、垃圾桶和一周日期导航。
- 左侧任务导航可整体折叠；观察到展开宽度约 `290px`，折叠后保留约 `45px` 的窄栏和展开按钮，中栏随之扩展，详情栏不被关闭。再次点击展开按钮可恢复导航。

### 3.3 任务列表

- 中栏头部包含侧栏折叠、视图标题、推荐任务、排序和页面更多操作。
- 排序菜单当前显示三组状态：分组（当前为时间）、排序（当前为时间）、顺序（当前为从旧到新）；“恢复默认时间顺序”在已是默认状态时置灰。
- 页面级更多菜单包含“视图”“隐藏已完成”“显示详细”“显示检查事项”“显示设置”“打印”。其中“显示详细”和“显示检查事项”是独立的信息密度开关，应在本项目中明确保存并反馈当前状态。
- 快速新增按当前上下文显示“添加任务至……”。
- 今天视图可在同一列表中混合分组展示倒数纪念日、任务、习惯和已完成内容。
- 普通任务行高约 `40px`，包含完成框、标题、标签、清单、重复、提醒和日期等紧凑元数据。
- 选中任务行保留稳定的浅色背景，与 hover 和多选状态可区分。
- 任务行更多菜单已观察到：日期、优先级、添加子任务、置顶、放弃、移动到、标签、开始专注、创建副本、复制链接、转换为笔记和删除。

### 3.4 任务详情

- 点击任务后在右栏打开对应详情，中栏保留上下文和滚动位置。
- 顶部快捷入口包含日期、重复和优先级。
- 主体包含标题、富文本描述、检查项、标签、所属清单和底部操作区。
- 描述区有 `/` 快速插入，支持正文、一至三级标题、有序/无序列表、检查项、引用、分割线、附件、子任务、标签和关联内容；行内格式包含加粗、斜体、下划线、删除线、代码和链接等。
- 检查项可拖动排序、完成、设置提醒和删除。
- 右栏内容水平内边距约 `24px`，顶部和底部工具区独立于中间滚动内容。
- 详情底部更多菜单已确认包含：添加子任务、置顶、放弃、标签、上传附件、开始专注、任务动态、保存为模板、创建副本、复制链接、转换为笔记、导出、打印和删除。实现时应按本项目已有数据契约开放；没有完整语义的操作不得只做空入口。
- 详情顶部已确认有完成状态、日期/时间、重复和优先级快捷入口；优先级在未启用或不可用时可呈禁用态。详情关闭应保持独立的方形热区，并确保 X 水平、垂直居中。

### 3.5 日期、重复与提醒弹层

- 日期弹层允许设置精确截止日期与时间；今天、明天、清除为快捷操作。查看态直接保存，编辑态只更新草稿并随详情保存提交。
- 重复弹层提供常用规则和自定义项。查看态选择预置规则后立即写入，编辑态只更新草稿；自定义 RRULE 在详情编辑态填写，并遵循既有任务 revision/sync 契约。
- 提醒是在线独立资源，不跟随任务离线草稿伪造成功。弹层支持相对截止时间、指定时刻、未完成时每日提醒，以及已有提醒更新/关闭；网络错误和 revision 冲突保留可重试状态。
- 日期、重复、提醒和优先级弹层互斥；关闭详情或切换任务时全部收起。异步提醒查询仅能更新发起查询的当前任务，不能覆盖后来选中任务的状态。

## 5. 统一设计与交互规范

### 5.1 结构和尺寸

- 桌面三栏使用 `240px minmax(370px, 1fr) minmax(320px, var(--task-detail-width))`。
- 右栏默认宽度为任务工作区可用宽度的 `36%`，初始值限制在 `400-560px`。
- 分隔条视觉宽度可为 `1px`，但可点击/拖动热区不小于 `8px`。
- 用户调整的详情宽度按账号保存到 localStorage；超出新视口时自动夹取，不产生水平滚动。
- 左、中、右栏各自滚动，左栏折叠、选择新任务或关闭详情时不得重置中栏滚动位置。

### 5.2 颜色和状态

- 任务行至少区分 default、hover、keyboard focus、selected、multi-selected、dragging 和 disabled。
- selected 必须使用稳定的主题语义色，不得与 hover 临时反馈相同；亮色和暗色主题下文字对比度均可读。
- 任务列表、详情栏和导航必须使用现有 `--card`、`--paper`、`--line`、`--ink`、`--muted`、`--accent` 等语义 token，不写死仅适配单一主题的颜色。
- 离线、待同步、冲突、保存中、保存失败必须有文字或图标状态，不只依赖 Toast。

### 5.3 密度和可访问性

- 鼠标主导的桌面任务行默认视觉高度目标为 `40px`；行内图标按钮的真实点击区不小于 `32px`。
- 触控模式和移动端的主操作热区不小于 `44px`，可通过增加行高而不是强行保持 40px。
- 所有图标按钮必须有 `aria-label`；折叠区域有 `aria-expanded`；分隔条使用 `role="separator"`、`aria-orientation="vertical"` 并支持键盘调宽。
- 拖动排序必须同时提供键盘或菜单式“上移/下移/移至……”备选路径。

## 6. 页面框架需求

### FE-LAYOUT-01 桌面常驻三栏

- 有任务被选中时，右栏立即显示对应详情；无选中项时显示轻量空状态，不应整栏消失导致中栏跳动。
- 点击新任务只切换右栏内容，不覆盖中栏，不改变当前列表的筛选、分组和滚动位置。
- 详情栏可关闭；关闭后中栏占用释放空间，再次点击任务恢复用户上次设置的宽度。

### FE-LAYOUT-02 分隔条

- pointer down 后进入拖动态，pointer move 实时调宽，pointer up/cancel 结束；拖动期间防止文字选中。
- 双击分隔条恢复默认宽度。
- `ArrowLeft/ArrowRight` 每次调整 `16px`，按住 Shift 时每次 `48px`。

### FE-LAYOUT-03 独立滚动与粘性区域

- 中栏标题、快速新增和工具条组成稳定头部，任务列表单独滚动。
- 右栏顶部属性区和底部工具区可见，中间描述、检查项和活动区滚动。
- 滚动条不应导致内容宽度明显跳变。

## 7. 任务导航需求

### FE-NAV-01 区域与顺序

任务导航按逆向证据保持以下顺序：

1. 固定视图：所有、今天、明天、最近 7 天、指派给我、收件箱、摘要。
2. 清单区：清单分组、未分组清单、归档任务入口、颜色/图标和待完成计数。
3. 筛选器区：本周、下周、无日期、无标签快捷视图，以及自定义智能清单和管理入口。
4. 标签区：标签层级、颜色、计数和管理入口。
5. 底部区：已完成、垃圾桶和一周日期导航。

没有多人协作指派字段时，“指派给我”显示真实空结果；“摘要”筛选当前账号逾期与今天到期的待办；“归档”筛选归档清单中的任务。不得展示未实现操作或伪造后端状态。

### FE-NAV-02 折叠与状态持久化

- 清单、标签、筛选器独立折叠，按账号持久化，不串用户。
- 清单分组的展开状态独立持久化。
- 切换路由不重置折叠状态；账号切换后立即加载新 scope 状态。

### FE-NAV-03 排序和反馈

- 清单、标签、筛选器内部可拖动排序；清单跨分组移动应同时更新分组归属和顺序。
- 拖动时显示抓手、半透明源项和清晰插入线；后端失败时恢复原顺序并显示可操作错误。
- 系统收件箱不可拖动、删除或改名。
- 行内编辑/删除按钮默认降低视觉噪音，hover、focus-within 或当前选中时再显示。

### FE-NAV-04 一周日期导航

- 底部显示包含今天的连续 7 天，有待办的日期显示弱提示点或数量。
- 点击日期进入对应当日任务上下文；如当前路由无法表达任意日期，先扩展 query 参数而不新增重复页面。

## 8. 任务列表需求

### FE-LIST-01 头部和快速新增

### FE-LIST-02 分组

- 今天/日期视图按产品语义显示通用分组：逾期、今天、之后、无日期、已完成。
- 在今天视图中，可将当日倒数日/纪念日、习惯打卡和任务作为独立类型分组混合展示。
- 分组标题显示计数、可折叠并按视图+账号保存状态。
- 不同类型使用稳定图标和语义色，但不得冒充为普通任务或共用不同的完成 API。

### FE-LIST-03 任务行

- 主行从左到右显示：完成框、标题、必要状态图标、标签/清单、日期、更多菜单。
- 子任务用缩进和弱连接线表达层级，不只依赖文案。
- 重复、提醒、检查项进度、子任务进度和专注数只在存在时显示。
- 窄宽度优先保留标题和日期，再按专注数、描述摘要、清单/标签的顺序逐级隐藏。

## 9. 任务详情编辑器需求

### FE-DETAIL-01 原位编辑

- 标题、开始时间、截止时间、全天、持续时长、清单、优先级、标签、重复和提醒均在右栏编辑。
- 新建和编辑都在右栏原位完成；移动端仍显示在任务页面内容流中，不出现 Drawer/Sheet。
- 字段更新继续经过 tasks store/local-first 操作链，不直接绕过同步引擎调 API。
- 简单选择项可即时保存；标题和描述采用失焦或短延迟保存。任务切换前必须 flush 当前编辑，失败时不静默丢失。

### FE-DETAIL-02 顶部快捷属性

- 顶部固定区展示完成、日期、重复、优先级、更多和关闭。
- 关闭按钮的 X 在方形热区中水平和垂直居中。
- 删除不放在高频顶层，位于更多菜单的危险操作区，并保留确认。

### FE-DETAIL-03 描述编辑

- 以 Markdown 作为服务端可持久化文本格式，前端提供所见即所得的快捷工具，不把未清洗 HTML 直接持久化。
- 首批支持正文、一至三级标题、有序/无序列表、引用、分割线、检查项、加粗、斜体、删除线、行内代码和链接。
- `/` 在空白块或行首打开插入菜单；不应拦截普通 URL 输入。
- 链接渲染仅允许 `http`/`https`/`mailto`，预览需转义原始 HTML。
- 附件入口只在真实上传 API 可用时显示；关联任务/笔记仍依赖后续数据能力，未实现时不提供空占位按钮。

### FE-DETAIL-04 检查项与子任务

- 检查项按结构化数组编辑，不继续使用“每行一个”文本域作为主交互。
- 支持新增、改名、完成/重开、拖动排序和删除；键盘上下移动作为无拖动备选。
- 检查项提醒只在后端已支持对应数据结构后开放；本期不将任务级提醒冒充为检查项级提醒。
- 子任务使用任务树语义，检查项是任务内属性；界面上必须明确区分。

### FE-DETAIL-05 活动和保存状态

- 活动区按时间倒序展示创建、完成/重开、移动、改期、优先级、提醒和重复变化。
- 顶部或底部显示“已保存 / 保存中 / 待同步 / 保存失败”，用户可从错误状态重试。
- 冲突时继续使用现有“采用服务端/保留本地”策略，不在右栏内静默覆盖。

### FE-DETAIL-06 评论与附件

- 评论区使用 `task_comment` 契约，支持在线分页、新增、编辑、软删除和冲突提示；正文复用 Markdown 渲染规则，创建使用幂等键。
- 附件区使用 `task_attachment` 契约，支持上传进度、下载、软删除、失败重试和大小/类型错误；离线时明确显示“待联网”，不得伪装上传成功。
- 评论与附件动作完成后刷新活动时间线；切换任务前保留当前详情上下文，不丢失已保存内容。
